자주 묻는 질문

일반

"kexify"는 무슨 뜻인가요?

Keys simplified, 즉 "간단해진 키"입니다. 그게 전부예요.

kexify란 무엇인가요?

독립된 키 조각 두 개를 함께 만드는 자기 보관형 MPC 지갑입니다. 한 조각은 브라우저에, 한 조각은 서버에 있습니다. 하나의 개인 키는 어디에도 존재하지 않으며, 어느 쪽도 전체 키를 가지고 있지 않습니다.

MPC란 무엇인가요?

다자간 연산(Multi-Party Computation)은 여러 참여자가 각자의 입력을 드러내지 않고 함께 계산하는 암호 기술입니다. kexify에서는 키 조각 두 개가 하나의 개인 키로 합쳐지지 않은 채 거래에 서명합니다.

kexify는 오픈 소스인가요?

네. Coinbase의 cb-mpc 라이브러리를 기반으로 합니다 (우리 포크). 웹 앱은 MIT 라이선스의 오픈 소스입니다: kexify-web. 서버와 iPhone 앱은 아직 오픈 소스가 아닙니다.

kexify는 정말 무료인가요?

무료 플랜은 영원히 무료이며 광고가 없고, 기본 보안 기능을 모두 포함합니다. 일일 한도, 신뢰하는 주소, 무제한 승인 차단, 위험한 주소 검사, 동결, 백업, 복구 모드입니다. 운영 비용이 드는 기능을 위해 프리미엄 플랜을 계획하고 있습니다. 예를 들면 iPhone을 승인 기기로 쓰는 기능, 위험 검사가 포함된 정밀 거래 시뮬레이션, 즉시 알림입니다. 가격은 아직 정해지지 않았습니다. 기본 보안 기능이 유료로 바뀌는 일은 없습니다.

kexify에는 왜 스왑, 스테이킹, DeFi 기능이 없나요?

의도한 설계입니다. 지갑은 보관과 서명, 한 가지를 잘해야 합니다. 스왑, 대출, 브리지는 1inch, Aave, MyEtherWallet 같은 dApp이 이미 잘 해결하고 있어요. WalletConnect로 어디든 연결하세요. 기능이 적으면 버그도 적고 공격 표면도 작습니다.

설계 철학은 무엇인가요?

세 가지 원칙이 있습니다. 단순하게, 지갑에만 집중하고, 사용성과 보안만 위해 다듬는 것입니다. 모든 기능은 이 기준을 거칩니다. 지갑을 더 쓰기 쉽게 하거나 더 안전하게 하지 않으면 넣지 않습니다.

보증이나 보장이 있나요?

아니요. kexify는 개인 프로젝트로, 현재 상태 그대로 제공되며 보증은 없습니다. 키와 자금은 본인이 책임져야 합니다. 다만 웹 앱의 코드는 오픈 소스이니 어떻게 작동하는지 직접 확인할 수 있습니다.

kexify는 누구를 위한 건가요?

두 부류를 위한 것입니다. 하나는 암호화폐가 처음이라 흔한 실수를 막아 주는 지갑을 원하는 사람입니다. 시드 문구가 없고, 일일 한도가 있으며, 서버가 위험한 서명을 거부합니다. 다른 하나는 WalletConnect, 테스트넷, 자신의 RPC, 그리고 우리 서버에 의존하지 않는 탈출 방법을 원하는 개발자입니다.

iPhone 앱이 있나요?

테스트 중이며 아직 App Store에는 없습니다. my.kexify.app의 웹 앱은 iPhone의 Safari를 포함한 최신 브라우저에서 지금 바로 쓸 수 있습니다.

보안

내 키는 누가 가지고 있나요?

전체 키를 가진 사람은 아무도 없습니다. 한 조각은 브라우저에 (패스키 또는 암호 문구로 암호화), 다른 한 조각은 서버에 (AES-256-GCM으로 암호화) 있습니다. 서명하려면 둘이 함께해야 합니다.

서버가 중단되면 어떻게 되나요?

복구 모드를 사용하세요. 미리 서버 키 조각을 내보내 두면 (전문가 모드에서), 브라우저에서 두 조각으로 로컬 서명할 수 있습니다. 프런트엔드는 오픈 소스이고, 두 조각을 전체 키로 합치는 CLI 도구도 있습니다. 서버는 필요 없습니다.

서버가 내 자금을 훔칠 수 있나요?

아니요. 서버는 조각 하나만 가지고 있어서 혼자서는 서명할 수 없습니다. 2-of-2 MPC 프로토콜이 설계상 한쪽만의 서명을 막습니다. 프런트엔드는 오픈 소스이므로 코드를 직접 감사하고 직접 호스팅할 수도 있습니다.

키 조각은 어떻게 저장되나요?

브라우저: WebAuthn 패스키 PRF 또는 암호 문구(PBKDF2)로 AES-GCM 암호화. 서버: 사용자별 HKDF 파생 키로 AES-256-GCM 암호화. 전송 구간은 모두 TLS 1.3.

GoPlus 사기 검사란 무엇인가요?

공동 서명하기 전에 서버가 받는 주소(토큰 승인이면 승인받는 주소)를 GoPlus Security의 사기, 피싱, 제재 대상 주소 데이터베이스와 대조합니다. 주소에 표시가 있으면 서버가 서명을 거부합니다. 모든 지갑에서 설정 없이 켜져 있습니다. GoPlus가 제때 응답하지 않으면 전송은 차단되지 않으므로, 보장이 아니라 추가 안전장치로 생각하세요.

ZenGo 같은 다른 MPC 지갑과 무엇이 다른가요?

둘 다 MPC를 씁니다. kexify에서는 키 조각 두 개를 내보내 우리 서버 없이 서명할 수 있고, 공동 서명자가 내가 직접 정한 규칙(일일 한도, 신뢰하는 주소, 한도 초과 시 대기)을 적용하며, 웹 앱이 오픈 소스입니다.

MPC와 정책 엔진은 어떻게 함께 작동하나요?

열쇠가 두 개 필요한 금고를 떠올려 보세요. 하나는 내가, 하나는 서버가 가지고 있고, 어느 쪽도 혼자서는 금고를 열 수 없습니다. 서버는 경비원 역할도 합니다. 열쇠를 돌리기 전에 내가 정한 규칙을 확인해요. 금액이 지출 한도 안인가? 승인된 목록에 있는 주소인가? 계정이 동결되지 않았나? 규칙을 하나라도 어기면 서버는 공동 서명을 거부하고, 거래는 그냥 일어나지 않습니다.

서버가 규칙을 적용한다면, 부당하게 나를 막을 수도 있나요?

서버는 내가 직접 정한 규칙만 적용합니다. 서버와 의견이 맞지 않더라도 빠져나갈 길이 있습니다. 키 조각 두 개를 내보내 복구 모드에서 완전히 혼자 거래에 서명하면 됩니다. 서버가 내 자금을 인질로 잡을 수는 없습니다.

사용법

어떤 블록체인을 지원하나요?

EVM 체인(Ethereum, Base, Avalanche, Polygon, Arbitrum, BSC...), Bitcoin, Solana, XRP, TRON, TON, Algorand, Cardano, Stellar, Litecoin, Bitcoin Cash와 각 체인의 테스트넷, 토큰을 지원합니다.

거래에는 어떻게 서명하나요?

앱에서 직접 시작하거나 WalletConnect로 연결하세요. 두 키 조각이 몇 차례 MPC 라운드에 참여해 보통 몇 초 안에 유효한 서명을 만듭니다.

정책 엔진이란 무엇인가요?

내가 스스로 정하는 보안 계층입니다. 서버가 공동 서명하기 전에 적용할 규칙을 설정할 수 있어요. 누군가 내 브라우저에 접근하더라도 정책이 할 수 있는 일을 제한합니다.

어떤 종류의 정책을 설정할 수 있나요?

일일 한도: 최근 24시간 기준 USD 금액. 보낼 곳: 어디든, 또는 신뢰하는 주소만. 한도 초과 시: 전송을 차단하거나, 1시간 또는 24시간 기다린 뒤 통과시킵니다. 모두 서버가 공동 서명하기 전에 적용합니다. 내 규칙과 별개로 무제한 토큰 승인과 표시된 주소는 항상 거부됩니다. 전문가 모드에는 사용자 지정 규칙 편집기도 있습니다.

24시간 대기 시간은 왜 있나요?

공격자가 규칙을 느슨하게 바꾸고 곧바로 악용하는 일을 막기 위해서입니다. 한도를 높이는 것처럼 규칙을 느슨하게 하는 변경은 24시간 기다려야 합니다. 규칙을 더 엄격하게 하는 변경은 바로 적용됩니다. 내가 바꾼 게 아니라면 계정을 동결할 시간이 있습니다.

계정을 동결할 수 있나요?

네. kexify 보안 이메일에 있는 동결 링크를 한 번 클릭하면 됩니다. 바로 적용되어 모든 서명이 차단됩니다. 동결을 풀려면 패스키(또는 지갑의 증명)가 필요하고 그다음 24시간을 기다려야 해서, 로그인 정보를 훔친 사람이 빠르게 풀 수는 없습니다.

전문가 모드란 무엇인가요?

무료로 쓸 수 있는 고급 제어 기능 모음입니다. 테스트넷, UTXO 선택, Bitcoin과 Litecoin의 Replace-By-Fee 가속, 사용자 지정 nonce와 수수료, 서명 전용 모드와 별도 전송, 원시 메시지 서명, 체인별 사용자 지정 RPC와 익스플로러, JSON 설정 편집기, 사용자 지정 정책 규칙, 키 조각 전체 백업을 지원합니다. 기본으로 꺼져 있으며 설정에서 켜세요.

이메일 없이 kexify를 쓸 수 있나요?

네. 익명 로그인으로 이메일이나 개인 정보 없이 지갑을 만들 수 있습니다. 키 조각은 브라우저에 로컬로 저장되고 암호 문구로 보호됩니다. 이 모드는 블록체인 키 관리를 이해하는 기술 사용자를 위한 것입니다. 암호 문구와 키 조각을 모두 잃어버리면 계정을 복구할 방법이 없습니다.

제한 사항

지갑을 하나만 만들 수 있는 이유는 무엇인가요?

지갑마다 암호화된 키 조각이 서버에 저장되고 서명에 서버 처리 시간도 쓰이므로, 무료 플랜은 계정당 지갑 하나입니다. 이 제한이 생기기 전에 만든 지갑은 계속 쓸 수 있습니다. 분리된 지갑을 더 쓰는 기능은 프리미엄으로 계획 중입니다.

거래당 입력이 50개(UTXO)로 제한되는 이유는 무엇인가요?

MPC 서명은 브라우저와 서버 사이에서 여러 차례 연산을 주고받아야 합니다. UTXO 체인(Bitcoin, Litecoin 등)에서는 입력마다 서명이 따로 필요합니다. 50개로 제한하면 서명 시간이 적당하게 유지되고 서버도 보호됩니다. 대부분의 거래에는 입력 50개면 충분합니다.

RPC 연결이 가끔 느리거나 불안정한 이유는 무엇인가요?

kexify는 대부분의 체인에서 기본으로 무료 공개 RPC 엔드포인트를 사용합니다. 이런 엔드포인트는 요청 제한이 걸리거나, 붐비거나, 가끔 중단되기도 합니다. 더 안정적이고 빠르게 쓰려면 전문가 모드를 켜고 설정에서 기본 RPC를 직접 마련한 엔드포인트(Alchemy, Infura, QuickNode 등)로 바꾸세요. 대부분 API 키만 있으면 넉넉한 무료 등급을 제공합니다.

이메일과 서명 요청에도 제한이 있나요?

네. 남용을 막기 위해 매직 링크 이메일, API 요청, 서명 작업 모두 요청 횟수가 제한됩니다. 제한에 걸리면 잠시 기다렸다가 다시 시도하세요. 일반적인 사용에는 충분히 넉넉하며, 평소와 다른 이용 패턴이 있을 때만 적용됩니다.

kexify는 왜 Cloudflare Turnstile을 사용하나요?

Turnstile은 개인정보 친화적인 CAPTCHA 대안으로, 백그라운드에서 보이지 않게 작동합니다. 성가신 퍼즐이나 추적 없이 봇과 자동화된 남용으로부터 서비스를 지킵니다. 느낄 일이 거의 없을 거예요.

개발자

테스트넷을 쓸 수 있나요?

네. 전문가 모드를 켠 뒤 설정에서 테스트넷을 켜세요. 지원 목록: Ethereum Sepolia, Base Sepolia, Solana devnet과 testnet, TRON Nile과 Shasta, Bitcoin과 Litecoin testnet, XRP, Stellar, TON, Algorand 테스트넷, Cardano PreProd.

어떤 WalletConnect 메서드를 지원하나요?

WalletConnect v2입니다. EVM: eth_sendTransaction, personal_sign, eth_sign, eth_signTypedData_v4. Solana: solana_signTransaction, solana_signAndSendTransaction, solana_signMessage. TRON: tron_signTransaction, tron_signMessage. 모든 요청은 일반 전송과 같은 검토와 서버 검사를 거칩니다.

명령줄 도구가 있나요?

네, kexify-web 저장소에 있는 Bun 기반 CLI입니다. 두 키 파일을 입력으로 받습니다. recover는 개인 키(16진수, Bitcoin은 WIF)를 복원하고 주소를 출력합니다. connect는 두 키 조각으로 WalletConnect 요청을 로컬에서 서명하며 kexify 서버가 필요 없습니다.

기술

어떤 암호 기술을 사용하나요?

EVM/Bitcoin 체인에는 ECDSA(secp256k1), Solana/Stellar에는 EdDSA(Ed25519)를 사용합니다. 브라우저에서 직접 실행되는 Coinbase의 cb-mpc WASM 라이브러리로 구동됩니다.

cb-mpc란 무엇인가요?

Coinbase의 임계값 암호 라이브러리입니다. 우리는 브라우저에서 실행되도록 WebAssembly로 컴파일한 포크를 사용합니다.
