Frequently Asked Questions

General

What does "kexify" mean?

Keys simplified. That's it.

What is kexify?

A self-custodial MPC wallet where two independent key shares are created together — one in your browser, one on the server. No single private key ever exists. Neither party holds the full key.

What is MPC?

Multi-Party Computation — a cryptographic technique where multiple parties compute a function together without revealing their individual inputs. In kexify, two key shares sign a transaction without ever combining into a full private key.

Is kexify open source?

Yes. Built on Coinbase's cb-mpc library (our fork). The web app is open source under the MIT license: kexify-web. The server and the iPhone app are not open source yet.

Is kexify really free?

The free plan is free forever, with no ads, and it includes all the basic safety: the daily limit, trusted addresses, the unlimited-approval block, the risky address check, freeze, backup and recovery mode. A Premium plan is planned for features that cost money to run, such as an iPhone approval device, offline QR signing and instant alerts. It is coming soon and its price is not set yet. Basic safety will never move behind a paywall.

Why doesn't kexify have swaps, staking, or DeFi features?

By design. A wallet should do one thing well — hold and sign. Swaps, lending, and bridges are already solved by dApps like 1inch, Aave, and MyEtherWallet. Connect to any of them via WalletConnect. Fewer features means fewer bugs and a smaller attack surface.

What is the design philosophy?

Three principles: keep it simple, stay focused on being a wallet, and optimize only for UX and security. Every feature decision is filtered through these. If it doesn't make the wallet easier to use or more secure, it doesn't ship.

Is there any warranty or guarantee?

No. kexify is a personal project provided as-is, with no warranty. You are responsible for your own keys and funds. That said, the web app's code is open source, so you can check how it works.

Who is kexify for?

Two groups. People who are new to crypto and want a wallet that stops the usual mistakes: no seed phrase, a daily limit, and a server that refuses risky signatures. And developers who want WalletConnect, testnets, their own RPC and a way out that does not depend on our server.

Is there an iPhone app?

It is in testing and not on the App Store yet. The web app at my.kexify.app works today on any modern browser, including Safari on iPhone.

Security

Who holds my keys?

Nobody holds the full key. One share is in your browser (encrypted with passkey or passphrase), the other on the server (encrypted with AES-256-GCM). Both must cooperate to sign.

What if the server goes down?

Use Recovery Mode. Export your server key share beforehand (in Expert mode), then sign locally in your browser with both shares. The frontend is open source, and there's also a CLI tool to combine both shares into a full key. No server needed.

Can the server steal my funds?

No. The server only has one share — it cannot sign alone. The 2-of-2 MPC protocol prevents unilateral signing by design. The frontend is open source — you can audit the code and even self-host it.

How are key shares stored?

Browser: AES-GCM encrypted with WebAuthn passkey PRF or passphrase (PBKDF2). Server: AES-256-GCM with per-user HKDF-derived key. All in transit: TLS 1.3.

What is GoPlus fraud check?

Before co-signing, the server checks the recipient (or the spender of a token approval) against GoPlus Security's database of scam, phishing and sanctioned addresses. If the address is flagged, the server refuses to sign. It is on for every wallet with no setup. If GoPlus does not answer in time, the send is not blocked, so treat it as an extra net, not a guarantee.

How is kexify different from other MPC wallets like ZenGo?

Both use MPC. With kexify you can export both key shares and sign without our server, the co-signer enforces rules you set yourself (daily limit, trusted addresses, a wait above the limit), and the web app is open source.

How do MPC and the Policy Engine work together?

Think of it like a safe that needs two keys. You hold one key, the server holds the other. Neither can open the safe alone. But the server also acts as a guard — before turning its key, it checks your rules: Is this amount within the spending limit? Is this address on the approved list? Is the account frozen? If any rule is violated, the server refuses to co-sign and the transaction simply can't happen.

If the server enforces rules, can it also block me unfairly?

The server only enforces rules you set yourself. And if you ever disagree with the server, you have an exit: export both key shares and sign transactions completely on your own in Recovery Mode. The server can never hold your funds hostage.

Usage

Which blockchains are supported?

EVM chains (Ethereum, Base, Avalanche, Polygon, Arbitrum, BSC...), Bitcoin, Solana, XRP, TRON, TON, Algorand, Cardano, Stellar, Litecoin, Dogecoin, and Bitcoin Cash — plus their testnets and tokens.

How do I sign transactions?

Initiate from the app or connect via WalletConnect. Both key shares take part in a few MPC rounds, usually a few seconds, to produce a valid signature.

What is the Policy Engine?

A self-imposed security layer that lets you set rules the server enforces before co-signing. Even if someone gains access to your browser, policies limit what they can do.

What types of policies can I set?

Daily limit: a USD amount per rolling 24 hours. Send to: anywhere, or trusted addresses only. Above the limit: block the send, or let it go through after a 1 or 24 hour wait. All are enforced by the server before it co-signs. On top of your rules, unlimited token approvals and flagged addresses are always refused. Expert mode also has a full custom rule editor.

Why is there a 24-hour cooling period?

To stop an attacker from loosening your rules and using them right away. A change that makes your rules looser, like a higher limit, waits 24 hours. A change that makes them stricter applies at once. If you did not make the change, you have time to freeze your account.

Can I freeze my account?

Yes, with one click on the freeze link in kexify's security emails. It takes effect at once and blocks all signing. Unfreezing needs your passkey (or a proof from your wallet) and then a 24-hour wait, so someone who stole your login cannot undo it quickly.

What is Expert Mode?

A free set of advanced controls: test networks, UTXO selection, Replace-By-Fee speed-up for Bitcoin and Litecoin, custom nonce and fees, sign-only mode with separate broadcast, raw message signing, custom RPC and explorer per chain, a JSON config editor, custom policy rules and full key share backup. It is off by default; turn it on in Settings. Dogecoin has no RBF, so DOGE sends cannot be sped up.

Can I use kexify without providing an email?

Yes. Anonymous login lets you create a wallet without any email or personal information. Your key shares are stored locally in the browser, secured with a passphrase. This mode is designed for technical users who understand blockchain key management — there's no account recovery if you lose your passphrase and key shares.

Limitations

Why can I create only one wallet?

Each wallet keeps an encrypted key share on the server and uses server time to sign, so the free plan has one wallet per account. Wallets created before this limit keep working. More sub-accounts are coming with Premium.

Why is there a limit of 50 inputs per transaction (UTXO)?

Each MPC signature requires multiple rounds of computation between your browser and the server. On UTXO chains (Bitcoin, Litecoin, etc.), every input needs a separate signature. Capping at 50 keeps signing time reasonable and protects the server. For most transactions, 50 inputs is more than enough.

Why are RPC connections sometimes slow or unstable?

kexify uses free public RPC endpoints by default for most chains. These can be rate-limited, congested, or occasionally down. For better reliability and speed, turn on Expert mode, go to Settings and replace the default RPC with your own endpoint (from Alchemy, Infura, QuickNode, etc.) — most offer generous free tiers with an API key.

Are there limits on emails and signing requests?

Yes. Magic link emails, API requests, and signing operations are all rate-limited to prevent abuse. If you hit a limit, wait a short while and try again. These limits are generous enough for normal use — they only kick in under unusual activity patterns.

Why does kexify use Cloudflare Turnstile?

Turnstile is a privacy-friendly CAPTCHA alternative that runs invisibly in the background. It protects the service from bots and automated abuse — without annoying puzzles or tracking. You should rarely notice it.

Developers

Can I use test networks?

Yes. Turn on Expert mode, then turn on test networks in Settings. Available: Ethereum Sepolia, Base Sepolia, Solana devnet and testnet, TRON Nile and Shasta, Bitcoin and Litecoin testnet, XRP, Stellar, TON and Algorand testnets, and Cardano PreProd.

Which WalletConnect methods are supported?

WalletConnect v2. EVM: eth_sendTransaction, personal_sign, eth_sign, eth_signTypedData_v4. Solana: solana_signTransaction, solana_signAndSendTransaction, solana_signMessage. TRON: tron_signTransaction, tron_signMessage. Every request goes through the same review and server checks as a normal send.

Is there a command-line tool?

Yes, a Bun CLI in the kexify-web repo. It takes your two key files. recover rebuilds the private key (hex, or WIF for Bitcoin) and prints your addresses. connect signs WalletConnect requests locally with both key shares, with no kexify server.

Technical

What cryptography is used?

ECDSA (secp256k1) for EVM/Bitcoin chains, EdDSA (Ed25519) for Solana/Stellar. Powered by Coinbase's cb-mpc WASM library running directly in your browser.

What is cb-mpc?

Coinbase's threshold cryptography library. We use a fork compiled to WebAssembly for in-browser execution.
